## 实验结果应如何解读

完整紧凑编码在 h=4 时为 4,392 / 2,280 / 1,224 字节；显式公钥编码为 8,648 / 4,424 / 2,312 字节。都包含 8 字节实验格式头，公钥格式为 38 字节。这些数字不能混写成标准 XMSS、标准 WOTS+ 或 Bitcoin 链上 witness 大小。

新计时来自 CPython 3.7.3、Darwin 24.6.0、x86_64 进程报告，不能据此断言物理 CPU 或是否经转译运行。它与旧计时不能计算“优化提速倍数”。两种验证模式的细小差异没有做统计显著性结论。

## 尚不能诚实地称为“JCE 投稿定稿”的问题

1. **创新性仍有限。** 当前合理定位是工程复现/案例研究。审稿人可能认为小型自研原型的错误修复不足以支撑完整研究论文。状态管理原则、公钥恢复和 Winternitz 权衡本身均不是新发现。需要由作者确定要主张的可区分贡献，并扩大验证范围。
2. **缺少标准实现的同平台对照。** 目前无经过独立向量验证的 XMSS/LMS/SLH-DSA 实测对照。新实验有意义，但不能支持“更安全、更快、优于标准方案”。
3. **持久状态模型尚无系统实证。** 52 状态的模型检查不等于真实磁盘崩溃恢复、并发、备份回滚或硬件故障测试。若以安全恢复为核心贡献，这些实验不可缺少。
4. **外部复现材料尚未发布。** 需要真实的代码仓库、冻结版本/归档标识和使用说明；只有本地路径不足以让外部审稿人复现。
5. **作者与声明信息缺失。** 作者姓名、单位、通讯邮箱、贡献、资助和利益冲突必须由作者提供。未擅自填写“无利益冲突”或虚构单位。
6. **HTML 不是最终投稿源文件。** 如投 JCE，需按期刊说明整理 LaTeX 或 Word，并提供可编辑源文件与适用的 PDF。本文保留 HTML 为审阅主稿，未擅自变更交付格式。

JCE 官方说明要求摘要 150–250 词、4–6 个关键词、相应作者信息与声明，并说明可编辑源文件要求。参见：[Journal of Cryptographic Engineering — Submission guidelines](https://link.springer.com/journal/13389/submission-guidelines)。具体提交时应再次核对。
